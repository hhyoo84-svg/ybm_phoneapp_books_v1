# 전화영어 교재 뷰어 — 데이터 매칭 (v2 블록 구조)

레슨 데이터(`Book.load` · `data/lesson-01.json`)와 ybmlms 교재 데이터(교재 타입 1–13)의 대응표.

- `data/lesson-01.json`의 Daily Life 내용은 **디자인 샘플**이다. ybmlms 실데이터가 아니다.
- `data/lesson-172855.json` = 실교재 Part 1–6(`data/source/lesson-172855-real.json`) + Part 1 문장 예시 블록 + 나머지 타입 확인용 Part 7–16(lesson-01 샘플 · 4타입 A/B 예시)
- 타입 기준: 전화화상팀 「전화화상 모바일 교재 타입별 정리 (26_0813).pptx」 + ybmlms ITEM 추출 데이터(11/4)
- ⚠ 표시는 확인이 필요한 항목 (6장)
- 화면을 그리는 코드: `js/blocks.js` `RENDER[block.type]`

## 1. 전체 구조

```
레슨
├─ course · lesson · lessons      표지 · 헤더
└─ parts[]                         파트 = 화면 단위 (Part 번호 순서)
   ├─ title · desc · teacher       파트명 · 파트 설명 · TG
   └─ blocks[]                     블록 = 교재 타입 1개 (ybmlms ITEM 그룹 1개)
      └─ items[]                   ITEM 행 (순서대로)
```

| 데이터 | ybmlms | 화면 |
|---|---|---|
| `course.lang` | 과정 언어 | 언어별 컬러 (`en` · `zh` · `ja`) |
| `course.label` · `title` · `titleEn` · `desc` | 과정 정보 | 표지 |
| `course.photo` · `lesson.photo` | (신규) | 레슨 사진 고정 시 파일 이름. 없으면 규칙으로 선택 (README 4장) |
| `lesson.number` | 레슨 번호 | 헤더 `LESSON 01` · 표지 현재 레슨 |
| `lesson.closing` | 레슨 마무리 문구 (영문 · 한글) | 마지막 파트 끝 박스 |
| `lessons[] { title, desc }` | 과정의 레슨 목록 | 표지 레슨 목차 |
| `parts[]` | 레슨의 Part 목록 | 파트 1 – n |
| `parts[].blocks[]` | 파트(`part_idx`)의 ITEM을 `item_type` 단위로 묶은 것 (4장) | 파트 안에서 위에서 아래로 |
| `blocks[].items[]` | ITEM 행 (`item_order` 순) | 문항 |

## 2. 파트 · 블록 공통 필드

| 데이터 | ybmlms | 화면 |
|---|---|---|
| `part.title` | 파트명 | 히어로 제목 · 접힌 헤더 · 파트 목록 |
| `part.desc` | 파트 설명 | 히어로 설명 |
| `part.teacher` | TG (파트 수업 진행 가이드) | 강사 가이드 박스. 없으면 박스 없음 |
| `block.type` | 교재 타입 (3장) | 블록 템플릿 |
| `block.heading` | 파트 소제목 ⚠ | 블록 맨 위 라벨 (예: `Part 3 (Q5~7) of the test`) |
| `block.label` | 내용 소제목 (1타입 등) | 회색 칩 |

## 3. 블록 타입별 매칭

배열 항목(`items`)은 한 줄 = ITEM 한 건. 배열 안 순서가 곧 필드다.

| 교재 타입 | `type` | 샘플 위치 | 필드 대응 |
|---|---|---|---|
| 1TYPE | `words` | Part 1 | `label` = 내용 소제목<br>`items[]` = `[영문, 한글해석]`<br>항목 중 하나라도 문장(문장 부호로 끝나거나 40자 초과)이면 블록 전체를 문장 크기 · 한 줄 배치로 자동 전환 (`B.SENTENCE_LENGTH`) |
| 2TYPE | `qa` | Part 2 | `items[]` = `[영문(강사가 말함), 한글 정답]` — 단어 · 문장 · A/B 문장 모두 한 쌍. 정답이 비면 버튼 없음. 패턴 연습 · 자유 대화처럼 소제목 · Tip이 칸 안에 들어간 항목도 이 블록 (실교재 샘플 Part 3 · 5 · 6) |
| 3TYPE | `drills` | Part 3 | `items[]` = `[문항 소제목, 영문(빈칸 "( )"), 보기입력, 한글해석]` |
| 4TYPE | `ab` | (샘플 없음) | `items[]` = `[A원문, A해석, B원문, B해석]` — 칸 안의 `A : … <br> B : …` 그대로 표시 |
| 5TYPE | `patterns` | Part 4 | `items[]` = `[예문 앞, 예문 뒤]` — 빈줄 + TIP(앞 / 뒤), 탭하면 정답 |
| 6TYPE | `topics` | Part 5 | `label` = 주제 문구<br>`items[]` = `[질문 영문, 한글해석]` |
| 7TYPE | `dialogue` | Part 6 | `items[]` = `[위치, 이름, 내용, 한글해석]` — 위치 `gray` 왼쪽 · `blue` 오른쪽 (`item_title`), 이름 = `item_eng_1`, 내용 = `item_kor_1` |
| 8TYPE | `expressions` | Part 7 | `items[]` = `[단어, 뜻, 예문, 예문 해석]` |
| 9TYPE | `phrases` | Part 8 | `items[]` = `[보기설명, [예문, 예문, …]]` |
| 10TYPE | `reading` | Part 9 | `passage` = `[본문, 본문 해석]`<br>`items[]` = `[질문, 한글해석]` |
| ⚠ | `sentences` | Part 10 블록 1 | `label` = 소제목<br>`items[]` = 문장 (①–⑩) |
| 11TYPE ⚠ | `picture` | Part 10 블록 2 | `picture` = `{ src, alt }` 이미지<br>`brainstorm[]` = `[그룹명, [질문, …]]` (가이드 켜면 노출) |
| 12TYPE | `respond` | Part 11 | `firstQuestion` = 첫 문항 번호(Q5)<br>`scenario` = `[박스 라벨, 문제, 문제 해석]`<br>`items[]` = `[질문, 질문 해석, 답변가이드, 답변가이드 해석]` |
| 13TYPE | `survey` | Part 12 | 12와 같음 + `picture`(선택)<br>`items[]` = `[질문(숨김텍스트), 답변가이드, 답변가이드 해석]` — '보기'를 눌러야 질문이 보임 |

- 한 파트에 여러 블록이 들어갈 수 있다(예: Part 10 = `sentences` + `picture`). 같은 타입이 반복돼도 된다.
- 모르는 `type`은 그리지 않고 콘솔에 경고를 남긴다.

## 4. ybmlms ITEM 테이블 → 블록 필드

컬럼: `item_idx, part_idx, item_type, item_order, item_num, item_title, item_eng_1, item_kor_1, item_eng_2, item_kor_2, item_example, use_type, regi_id, regi_date, edit_id, edit_date, group_num`

| 컬럼 | 뜻 | 화면 데이터 |
|---|---|---|
| `part_idx` | 소속 파트 | `parts[]` 한 개 |
| `item_type` | 교재 타입(1–13) | `block.type` |
| `item_order` | 파트 안 순서 | 블록 · 문항 순서 |
| `item_num` | 문항 번호 | 번호 배지 (비어 있으면 순서대로) |
| `group_num` | 묶음 번호 (0 = 묶음 없음) ⚠ | 블록 나누는 기준 후보 |
| `use_type` | 사용 여부 (`Y`) | `Y`만 표시 |

- 한 `part_idx` 안에 `item_type`이 다른 ITEM이 섞여 있다(예: 101459 = 4 · 9 · 11 · 12타입). → 파트 하나 = 블록 여러 개 구조가 맞다.
- 블록 = 같은 파트에서 `item_order` 순으로 이어지는, `item_type`(과 `group_num`)이 같은 ITEM 묶음.

## 5. 데이터 규칙

- 텍스트 칸은 `HTML_작성기준.md` 기준으로 화면에서 정리한다(줄바꿈 유지, 허용 태그만).
- 빈칸 문장(3타입)은 빈칸 자리를 `( )`로 쓴다.
- 이미지는 파일 이름만 (`"img-2.jpg"`). 폴더는 `core.js`가 붙인다 (README 4장).

## 6. 확인 요청 (⚠)

| 항목 | 확인 내용 | 대상 |
|---|---|---|

| 이미지 · TTS · 답변TG · 숨김텍스트 | ITEM 표의 어느 열 / 다른 표인지 | 개발 |

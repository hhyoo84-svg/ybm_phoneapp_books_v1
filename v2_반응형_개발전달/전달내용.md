## 반영 방법

### 방법 1. 같다면 — 파일 통째로 교체

### 방법 2. 다르다면(그 사이 수정됨) — 해당 부분만 병합
- 통째로 덮어쓰면 개발 쪽 수정이 사라지므로, 아래 "1. 파일별 변경 위치" 표를 보고 해당 부분만 넣습니다.

- 순서 · 짝 규칙
  - 가로 UI 블록은 기존 규칙 **뒤**에 와야 하므로 파일 맨 아래에 붙입니다 (`2026-11-04 · A` 날짜 주석이 달린 블록).

## 2. 작업별 설명

### A. 반응형 가로 UI
- **적용 범위** : 가로 폭 1024px 이상 + 클래스룸(수강중 · 예정 · 종료) · 스케줄. 1024px 미만(모바일 · 세로 태블릿)은 기존과 동일.
- **화면 틀** : 높이 `100dvh`, 폭 전체. 클래스룸과 스케줄이 같은 폭 (`shell.css` · `2026-11-04 · A` 주석).
- **클래스룸** : 왼쪽(강좌 · 입장 카드 · 예습) / 오른쪽(지난 수업 · 리포트 · 첨삭 · 질문/만족도). 왼쪽 예습 카드와 오른쪽 마지막 카드의 아래 끝을 맞춤. 사전학습 · AI학습 팝업이 열린 상태에서는 늘리지 않음.
- **스케줄** : 왼쪽(주간 카드 · 바로가기 · 수업 목록) / 오른쪽(월간 달력). 스크롤은 수업 목록만. 날짜를 누르면 왼쪽 주간과 목록이 해당 날짜로 이동.
- **`.classroom-side` 순서** : `classroom.css` 에서 `display:contents` 규칙(570줄 부근)이 가로 블록(573줄 부근~)보다 위에 있어야 함.
- **`schedule.js` 순서** : 가로 UI 코드(`2026-11-04 · A 스케줄 가로 UI` 주석 아래)는 위쪽에서 만든 `window.__scApi` 를 쓰므로 파일 맨 아래에 유지.
- **지원 브라우저** : 스케줄 가로 레이아웃에 `:has()` 사용 → Chrome 105+ / iOS Safari 15.4+.

### B. 모바일 세로 고정
- 안드로이드 설치형 · 전체화면에서는 `screen.orientation.lock('portrait')` 로 실제 잠김.
- iOS Safari · 일반 브라우저는 잠금 미지원 → 가로(폭 1000px 이하, 높이 500px 이하)로 돌리면 "화면을 세로로 돌려 주세요" 안내가 화면을 덮음. 세로로 돌리면 바로 복귀.
- 태블릿(높이 600px 이상)은 영향 없음.
- 앱 껍데기(웹뷰 / PWA manifest)에서 세로 고정을 걸면 더 확실함. 이 코드는 그 설정이 없는 환경용 보조 장치.

### C. 출석현황 수정안
1. **최고 기록 7회 삭제** — 칩 · `BEST` 변수 제거.
2. **횟수 → %** — 구간 시작(0%) → 25% → 50% → 75% → 완강(100%). **강좌 전체 횟수 기준**, 진행률 = `progressDone / progressTotal`. 메달 표기는 불꽃 · 25% · 50% · 75% · 완강.
3. **배지 + 진행률 병합** — 배지 5개가 막대 위 구간점. 달성한 배지만 보라색, 미달성은 회색 + 잠금. 별도 `출석 배지` 카드와 진행률 카드는 출석현황 팝업에서 제거(진행률 카드는 종료 강좌 요약에서도 쓰므로 마크업은 유지하고 팝업에서만 CSS로 숨김).
4. **카드 문구** — "연속 출석 N회 / 진행률 N% · 다음 배지까지 N회 남았어요". 남은 횟수 = `ceil(전체 횟수 × 다음 구간 %) − 출석 횟수`.
5. **와옹이** — 팝업을 열면 막대 시작에서 출발해 현재 진행 위치까지 달림 (연속 출석 3·7·14회는 만세, 30회 이상은 불꽃 모션 — 기존 규칙 유지).
6. **간격** — 달력 아래 범례(출석 · 연기/SKIP · 결석 · 수업 예정)와 통계 박스(출석 · 연기 · 취소/결석) 사이 24px.

### D. 다크모드 보완
- 기기가 다크모드일 때 `tokens.css` 의 다크 블록이 글자색은 밝게 바꾸는데, 앱 화면용 토큰(`--s3-*`, `--brand-selection-bg`)은 라이트 값 그대로여서 **밝은 배경 + 밝은 글자**가 되던 문제를 보완.
- 해결된 곳 : 클래스룸 `수강중` 탭 글자, 강좌명, 예습 말풍선 제목(오늘의 교재 등), 본문 배경 · 구분선.
- 아직 정식 다크모드는 아님 : 화면에 직접 지정된 색(하드코딩)은 다크 값이 없어 화면별 점검이 더 필요함. 다크모드를 정식 지원할지는 기획 확인 후 진행.
- 다크 대응 없이 항상 밝은 화면으로 고정하려면 `tokens.css` 의 다크 블록(`@media (prefers-color-scheme: dark)`)을 쓰지 않으면 됨.

### E. 수강 중 과정 없음 빈 화면 (B2C)
- 수강 중 탭에서 진행 중인 과정이 없을 때 : **강좌 슬라이드 영역 안에** 캐릭터 + "수강 중 과정이 없습니다." 표시. 입장 카드 · 예습 · 리뷰 영역은 숨김.
- 예정 · 종료 탭도 같은 형태 — "예정된 과정이 없습니다." / "종료된 과정이 없습니다." (목록 배열이 비었을 때 자동 출력).
- 시안에서는 수강중 롤링 **3번째 슬라이드**가 이 상태 (`data-empty="1"`). 실제 연동에서는 과정이 0개일 때 빈 슬라이드 하나만 두고 `#scrollArea` 에 `is-empty` 클래스를 주면 됨.
- 캐릭터는 기존 빈 화면 공통 규칙(`core.js` `EMPTY`)을 그대로 사용 — 추가 이미지 없음.
- 실서비스에서 과정이 0개일 때의 화면은 **`course-empty.html`**(이 폴더, 신규 1개)로 제공. 앱 셸(상단 로고·탭, 하단 내비)은 그대로 두고 본문만 `.course-empty` 로 교체한 정적 페이지이며, `css/` 파일은 이 폴더의 것을 그대로 사용(`tokens` · `base` · `components` · `shell` · `classroom` · `classroom-wide`). 예정 · 종료 탭은 같은 마크업에서 문구만 바꿔 사용.

### F. 가로 밀림 방지
- 본문 영역(`.scroll-area`)이 세로 스크롤만 하도록 가로는 `overflow-x:hidden`, 문서 · 앱 틀은 `overscroll-behavior:none` 으로 좌우로 끌려가지 않게 고정. 스케줄뿐 아니라 모든 화면에 공통 적용.
- 강좌 가로 스와이프, 스케줄 강좌 칩 스크롤은 각자 자기 영역 안에서만 움직이므로 영향 없음.

### G. 수업 후 카드 간격
- 수업리뷰 · 월말 리포트 · 주니어 첨삭 카드가 붙어 보이던 문제. 원인은 오른쪽 열 묶음 `.classroom-side` 에 모바일용 `display:contents` 가 빠져 있던 것(v2 폴더). `display:contents` 로 풀면 타임라인 간격 8px 이 적용되고, 여기에 4px 을 더해 12px 로 맞춤.

### H. 월간 하단 안내 칩 배경
- 월간 하단 "연기, 보강신청 등은 주별 스케줄에서 가능합니다." 칩이 달력 카드 끝에 걸쳐 뜨는데, 카드 아래 영역 색(`--s3-bg`)이 카드 색과 달라 칩 뒤 배경이 끊겨 보였음(다크모드에서 특히). 월간일 때만 영역 바닥색을 카드와 같게 맞춤.

### I. 교재 링크
- 예습 로드맵의 `오늘의 교재 > 교재 보기` 버튼을 누르면 `https://hhyoo84-svg.github.io/ybm_phoneapp_books_v1/book_v2/magazine.html` 이 새 창으로 열림. 실제 앱에서는 교재 화면 주소(강좌 · 레슨별 파라미터 포함)로 교체 필요.

### J. 구형 웹뷰 높이
- 앱(웹뷰)에서 위아래가 꽉 차지 않던 원인 추정: `height:100dvh` 를 지원하지 않는 웹뷰(Chrome 108 미만 기반)는 이 선언을 통째로 무시해 높이가 내용만큼만 잡힘. 같은 줄 앞에 `100vh` 를 먼저 선언해 대체값으로 사용. 같은 이유로 `dvh` 를 쓰는 다른 곳(가로 UI 높이, 빈 화면 최소 높이)에도 대체값 추가.
- 그래도 안 차는 기기가 있으면 앱 쪽에서 웹뷰 영역이 상태바 · 하단 내비게이션 바를 뺀 크기인지, `viewport-fit=cover` 와 안전영역 처리 여부를 같이 확인해야 함.

## 3. 서버 · 데이터 연동 시 확인할 점
- `attendance.progressDone`(출석 횟수), `attendance.progressTotal`(강좌 전체 횟수)가 진행률 · 배지 구간의 기준입니다. 현재는 `data/demo.json` 데모 값(50 / 120).
- `attendanceSteps` 의 숫자는 이제 **퍼센트**이고 이름은 배지명입니다. 연동 시 구간 기준을 %로 내려주세요. 배지명 중 '작심삼일 극복!'은 횟수 기준 때의 문구라 25%에 맞는 문구로 바꿀지 기획 확인이 필요합니다.
- 연속 출석 횟수(`STREAK`)는 제목(연속 출석 N회)과 달력 도장에만 쓰이고, 배지 달성 판단에는 쓰이지 않습니다.
- 와옹이 이미지는 `images/` 의 기존 파일을 사용합니다 (추가 이미지 없음).

## 4. 확인한 환경
- 390 · 820 · 1024 · 1280 · 1880px, 합치기 전과 같은 화면 (카운트다운 · 애니메이션 제외), 스크립트 오류 없음.
- 브라우저에서 이전 화면이 보이면 `Ctrl+Shift+R` (강력 새로고침) 후 확인.

## 2. 작업별 설명

### A. 반응형 가로 UI
- **적용 범위** : 가로 폭 1024px 이상 + 클래스룸(수강중 · 예정 · 종료) · 스케줄. 1024px 미만(모바일 · 세로 태블릿)은 기존과 동일.
- **화면 틀** : 높이 `100dvh`, 폭 전체. 클래스룸과 스케줄이 같은 폭 (`shell.css` 220–230).
- **클래스룸** : 왼쪽(강좌 · 입장 카드 · 예습) / 오른쪽(지난 수업 · 리포트 · 첨삭 · 질문/만족도). 왼쪽 예습 카드와 오른쪽 마지막 카드의 아래 끝을 맞춤. 사전학습 · AI학습 팝업이 열린 상태에서는 늘리지 않음.
- **스케줄** : 왼쪽(주간 카드 · 바로가기 · 수업 목록) / 오른쪽(월간 달력). 스크롤은 수업 목록만. 날짜를 누르면 왼쪽 주간과 목록이 해당 날짜로 이동.
- **`.classroom-side` 순서** : `classroom.css` 에서 `display:contents`(570)가 가로 블록(573~)보다 위에 있어야 함.
- **`schedule.js` 순서** : 가로 UI 코드(544~)는 위쪽에서 만든 `window.__scApi` 를 쓰므로 파일 맨 아래에 유지.
- **지원 브라우저** : 스케줄 가로 레이아웃에 `:has()` 사용 → Chrome 105+ / iOS Safari 15.4+.

### B. 모바일 세로 고정
- 안드로이드 설치형 · 전체화면에서는 `screen.orientation.lock('portrait')` 로 실제 잠김.
- iOS Safari · 일반 브라우저는 잠금 미지원 → 가로(폭 1000px 이하, 높이 500px 이하)로 돌리면 "화면을 세로로 돌려 주세요" 안내가 화면을 덮음. 세로로 돌리면 바로 복귀.
- 태블릿(높이 600px 이상)은 영향 없음.
- 앱 껍데기(웹뷰 / PWA manifest)에서 세로 고정을 걸면 더 확실함. 이 코드는 그 설정이 없는 환경용 보조 장치.

### C. 출석현황 수정안
1. **최고 기록 7회 삭제** — 칩 · `BEST` 변수 제거.
2. **횟수 → %** — 구간 시작(0%) → 25% → 50% → 75% → 완강(100%). **강좌 전체 횟수 기준**, 진행률 = `progressDone / progressTotal`. 메달 표기는 불꽃 · 25% · 50% · 75% · 완강.
3. **배지 + 진행률 병합** — 배지 5개가 막대 위 구간점. 달성한 배지만 보라색, 미달성은 회색 + 잠금. 별도 `출석 배지` 카드와 진행률 카드는 출석현황 팝업에서 제거(진행률 카드는 종료 강좌 요약에서도 쓰므로 마크업은 유지하고 팝업에서만 CSS로 숨김).
4. **카드 문구** — "연속 출석 N회 / 진행률 N% · 다음 배지까지 N회 남았어요". 남은 횟수 = `ceil(전체 횟수 × 다음 구간 %) − 출석 횟수`.
5. **와옹이** — 팝업을 열면 막대 시작에서 출발해 현재 진행 위치까지 달림 (연속 출석 3·7·14회는 만세, 30회 이상은 불꽃 모션 — 기존 규칙 유지).
6. **간격** — 달력 아래 범례(출석 · 연기/SKIP · 결석 · 수업 예정)와 통계 박스(출석 · 연기 · 취소/결석) 사이 24px.

## 3. 서버 · 데이터 연동 시 확인할 점
- `attendance.progressDone`(출석 횟수), `attendance.progressTotal`(강좌 전체 횟수)가 진행률 · 배지 구간의 기준입니다. 현재는 `data/demo.json` 데모 값(50 / 120).
- `attendanceSteps` 의 숫자는 이제 **퍼센트**이고 이름은 배지명입니다. 연동 시 구간 기준을 %로 내려주세요. 배지명 중 '작심삼일 극복!'은 횟수 기준 때의 문구라 25%에 맞는 문구로 바꿀지 기획 확인이 필요합니다.
- 연속 출석 횟수(`STREAK`)는 제목(연속 출석 N회)과 달력 도장에만 쓰이고, 배지 달성 판단에는 쓰이지 않습니다.
- 와옹이 이미지는 `images/` 의 기존 파일을 사용합니다 (추가 이미지 없음).

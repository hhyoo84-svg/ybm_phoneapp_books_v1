# 전화영어 앱 — Claude와 함께한 작업 플로우 요약

## 1. 투입 자료 · 초기 지침

- 시작점은 2026-08-21 "회의 내용" 문서 — YBM 실무 담당 회의 요청 메모: 교재를 웹·모바일웹·앱(B2C+B2B 공통) 구조로 새로 만들고, 13개 교재 타입별 UI를 디자인하며, TG(강사 가이드)는 별도 화면 없이 학습자 UI 위에 얹는 형태로 노출한다는 조건이 처음부터 명시돼 있었음. 사용빈도가 가장 높은 "일상회화(Daily Life)"부터 샘플 작업을 시작.
- 함께 투입된 자료 3종: `전화화상영어 APP_v2.1_260831.pptx`(TO-DO 영역·레이어 팝업 등 상세 와이어프레임 스펙), `전화화상 모바일 교재 타입별 정리(26_0813).pptx`, `전화화상 타입별 사용현황 26_0812.xlsx`(교재 타입별 실사용 데이터), `전화외국어 레퍼런스조사.pdf`(링글 등 경쟁 서비스 분석).
- 톤·스타일 지침은 처음부터 명확했음 — "민병철처럼 단색이 아니라 살짝 가미된 그라데이션", radius는 토스(Toss) UI를 벤치마킹. 이 지침이 이후 모든 시안의 컬러 작업 기준이 됨.
- 디자인시스템 참고자료로 당근마켓 Seed Design과 사내 회원가입 Figma 시스템을 Claude가 직접 비교 분석(2026-08-31) — 둘 다 학습 콘텐츠 UI를 커버하지 못한다는 결론을 내고, "토큰 체계·네이밍 방법론만 차용하고 컴포넌트는 전화영어 전용으로 설계"하는 방향을 제안했고, 실제로 이 방향대로 진행됨.

## 2. Claude가 한 일 vs 내가 결정한 것

**Claude가 수행한 작업**
- 초기 리서치·방법론 제안(위 Seed Design 비교분석)
- 시안 1~J, 리더형, 매거진형 등 다수의 HTML/CSS/JS 단일 파일 시안 구현
- 대규모 네이밍·토큰 통일 작업 — 색상 27종을 DS 토큰으로 매핑, Figma 변수 560개를 코드명과 동일하게 등록, `pop-`→`modal-` 같은 클래스 접두어를 스크립트(refactor.py)로 일괄 리팩터
- Figma MCP로 코드→Figma 변환 자동화(`dom2fig.js` → `compact.py` → `fbuild_head.js`) — HTML 요소를 그대로 Figma 레이어 32개·69개 화면 프레임으로 조립
- Playwright로 리팩터 전후 수십 개 상태×해상도의 computed style을 수치 비교해 "시각적으로 아무것도 안 바뀌었음"을 검증
- 이번 대화에서 직접 다룬 예: 시안 G(`index_v1.html`) 기준으로 인디고×틸 컬러를 업로드한 Canva 로고 레퍼런스의 틸→블루→바이올렛 그라데이션으로 교체, 히어로 영역 박스 제거(열린 레이아웃), 표지 전체 그라데이션화, 헤더 학습 도구 버튼을 태블릿→모바일 순으로 "펼친 상태"로 전환 — 매 라운드 스크린샷으로 확인하며 진행

**내가(또는 조직이) 결정한 것**
- 메인 컬러·그라데이션 톤, radius 스케일, DS 네이밍 방식(Figma 변수명=코드 변수명 통일)
- 시안2 B안(스케일 반올림) 채택, 클래스룸 홈 Figma 재동기화 시 "기존 구조를 덮어쓰지 않고 신규 프레임으로 분리"
- 각 라운드 결과물의 최종 승인과 세부 디테일(버튼 위치, 간격, 톤) 피드백
- 조직 차원 결정: 2026-10-14 사업부 피드백으로 시안3 구조 확정, "AI 추천 매칭"→"자동 매칭" 용어 수정, 팀장 피드백으로 교재 메인 컬러는 기존 블루 계열 유지 지시, 2026-10-28 사업부 최종 회신으로 매거진형 채택·리더형 제외·"강사 가이드" 용어 통일

## 3. 방향이 바뀐 지점과 이유

- **레이아웃**: 카드스택형(A)·리더형(B)·매거진형(C) 세 후보를 비교 페이지로 나란히 검토 → 10/21 리더형을 1차로 메인 채택 → 10/26 매거진형·리더형 두 트랙을 동시에 다듬어 사업부에 전달 → **10/28 사업부 회신으로 매거진형 최종 채택, 리더형은 소스에서 제외**(참고용으로만 보관). 이 대화에서 방금 작업하던 리더형 헤더 버튼 수정도 이 흐름의 일부.
- **컬러**: 인디고/퍼플 단일톤 → 팀장 피드백("기존 앱 컬러인 블루+민트 계열은 유지하되 안 바뀐 느낌은 아니게") → 언어별(영/중/일) 구분이 필요해지면서 블루는 과다 사용으로 제외 → **퍼플(기본/영어)·코랄(중국어)·그린(일본어) 3색 체계**로 최종 수렴(10/26~28). 이번 대화에서 다룬 Canva 로고 기반 틸→블루→바이올렛 그라데이션 실험은 이 컬러 탐색 과정의 한 갈래였음.
- **디자인시스템 네이밍**: 시안별 제각각 변수명(`--purple`, `--ink` 등) → Seed Design 비교분석 이후 "Figma 변수명=코드 변수명" 통일 규칙으로 전환, 기존 시안 전체에 소급 적용.
- **Figma 작업 방식**: 원본 "리소스 디자인시스템" 파일이 브랜치를 지원하지 않는 요금제라, 복제본에서 작업한 뒤 수동으로 원본에 반영하는 우회 방식을 채택.

## 4. 최종 결과물

- **교재 뷰어**: `magazine.src.html` + `build.py`(사진·폰트 인라인 빌드) → 언어별 단일 파일 `book-magazine-{en|zh|ja}.html`. 개발 전달은 `book/` 폴더 아래 `inc/css/js/data/images` + `산출물-수정금지(참고자료)/` + README·개발 확인사항 문서로 구성. 리더형 소스는 `_이전시안/1028_단일파일본/`에만 보존.
- **아티팩트**: 매거진형 최종본, 시안 비교 페이지, 리더형 coral·green(최종안에서는 제외됐지만 산출물로는 남아 있음 — 이번 대화에서 "모바일 헤더 버튼 펼치기" 수정을 적용한 파일들).
- **클래스룸/스케줄 쪽**은 v2 개발전달본(`app.src.html` + `build.py` → `app.html`, `screens.html`)과, Figma 변수·실제 마크업을 자동 채취해 만든 라이브 디자인시스템 문서(`ds.html`) 형태로 별도 산출.
- **Figma**: 디자인시스템 파일, 리소스 DS 원본, 작업 복제본 3개 — Primitive 색상 11~32개, Phone 브랜드 모드, 텍스트 스타일 11개, 화면 프레임 32~69개가 코드에서 역추출되어 등록됨.
- **Stitch·AI Studio로 넘길 때 쓴 프롬프트/정리본**: 이 프로젝트의 문서·메모리 어디에도 남아있지 않음. 그 핸드오프는 Claude 세션 바깥(로컬 작업 또는 다른 툴 화면)에서 이뤄진 것으로 보이며, 이 자료만으로는 복원이 안 됨 — 발표에서 이 구간은 "Claude에서 기획/방향을 정리 → 그 결과를 Stitch·AI Studio에 넘겨 시안 디벨롭"이라는 **흐름 자체**를 설명하고, 실제 프롬프트 텍스트는 따로 갖고 계신 자료(로컬 메모, 브라우저 히스토리 등)에서 보충하시는 걸 추천.

## 5. 시행착오

- 클래스룸 홈에서 요일 스트립(flex)과 월간 그리드(grid)의 컬럼 계산 방식이 달라 요일이 미세하게 어긋나는 버그, 예습 3단계 칩이 "팝업만 닫아도 완료로 보이는" 상태 로직 버그 — 둘 다 발견 후 수정.
- Figma 실측 팔레트(`#6D42BF`)와 코드가 정착한 브랜드 퍼플(`#5D4BE2`)이 한동안 달라 혼선이 있었고, 이후 코드 기준으로 정리.
- 한글 줄바꿈(word-break) 버그가 앱 전역에 산발적으로 남아 있던 것을 캡처로 지적("마이크"→"마이"+"크" 끊김)받은 뒤 전수 점검해 일괄 보정.
- Claude 작업 환경이 로컬 폰트(Pretendard)를 못 불러와 Figma 작업 때 IBM Plex Sans KR로 임시 대체 후 되돌리는 2단계 우회가 반복적으로 필요했음.
- 다른 세션이 같은 아티팩트 URL에 유사한 내용을 다른 제목으로 먼저 재배포해 충돌이 발생한 적이 있어, 전체 소스를 대조해 상위 호환임을 확인하고 재배포로 해결.
- **세션 단절**: 이번 대화 자체도 9/11~10/28 사이 약 1.5개월의 공백을 거치며 로컬 작업 파일이 모두 유실돼, 프로젝트 문서 검색과 아티팩트 목록 조회만으로 현재 상태를 처음부터 재구성해야 했음 — "AI한테 맡겨도 맥락이 끊기면 복구가 필요하다"는 걸 보여주는 실제 사례로 발표에 넣을 만함.

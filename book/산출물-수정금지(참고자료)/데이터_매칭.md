# 전화영어 교재 뷰어 — 데이터 매칭

`data/lesson-01.json`(BOOK_DATA)과 ybmlms 교재 데이터(교재 타입 1–13)의 대응표.

- `data/lesson-01.json`의 Daily Life 내용은 **디자인 샘플**이다. ybmlms 실데이터가 아니다.
- 타입 기준: 전화화상팀 「전화화상 모바일 교재 타입별 정리 (26_0813).pptx」
- ⚠ 표시는 타입 번호 확인이 필요한 파트 (6장)
- 화면을 그리는 코드: `js/parts.js` `RENDER[type]`

## 1. 전체 구조

| BOOK_DATA | ybmlms | 화면 |
|---|---|---|
| `course.lang` | 과정 언어 | 언어별 컬러 (`en` · `zh` · `ja`) |
| `course.label` · `title` · `titleEn` · `desc` | 과정 정보 | 표지 |
| `course.photo` · `lesson.photo` | (신규) | 레슨 사진 고정 시 파일 이름. 없으면 규칙으로 선택 (README 4장) |
| `lesson.number` | 레슨 번호 | 헤더 `LESSON 01` · 표지 현재 레슨 |
| `lessons[] { title, desc }` | 과정의 레슨 목록 (레슨명 · 레슨 설명) | 표지 레슨 목차 |
| `parts[]` | 레슨의 Part 목록 (등록 순서) | 파트 1 – n |

## 2. 파트 공통 필드

| BOOK_DATA | ybmlms | 화면 |
|---|---|---|
| `type` | 교재 타입 (아래 3장) | 본문 템플릿 선택 |
| `title` | 파트명 | 히어로 제목 · 접힌 헤더 · 파트 목록 |
| `desc` | 파트 설명 | 히어로 설명 |
| `teacher` | TG (파트 수업 진행 가이드) | 강사 가이드 박스 (강사 계정 + 버튼 켬) |
| 파트 순서 | Part 번호 | `PART 01` 표기 · 이동 순서 |

## 3. 파트별 매칭

배열 항목(`items`)은 한 줄 = 한 문항. 배열 안 순서가 곧 필드다.

| Part | `type` | 교재 타입 | 필드 대응 |
|---|---|---|---|
| 1 Vocabulary | `words` | 1TYPE | `label` = 내용 소제목<br>`items[]` = `[영문, 한글해석]` |
| 2 Q&A Warm-up | `qa` | 2TYPE ⚠ | `items[]` = `[A영문, A한글해석, B영문, B한글해석]` |
| 3 Choose & Complete | `drills` | 3TYPE ⚠ | `items[]` = `[문항 소제목, 영문(빈칸은 "( )"), 보기입력, 한글해석]` |
| 4 Pattern Practice | `patterns` | 5TYPE | `items[]` = `[예문 앞, 예문 뒤]` — 화면은 빈줄 + TIP(앞 / 뒤), 탭하면 정답 |
| 5 Talk About You | `topics` | 6TYPE ⚠ | `label` = 주제 문구<br>`items[]` = `[질문 영문, 한글해석]` |
| 6 Main Dialogue | `dialogue` | 7TYPE | `items[]` = `[대화자 위치("teacher" · "me"), 영문, 한글해석]` — 이름은 위치로 표시 |
| 7 Key Expressions | `expressions` | 8TYPE | `items[]` = `[단어, 뜻, 예문, 예문 해석]` |
| 8 Comprehension Check | `phrases` | 9TYPE | `items[]` = `[보기설명, [예문, 예문, …]]` |
| 9 Reading | `reading` | 10TYPE | `passage` = `[본문 영문, 본문 해석]`<br>`items[]` = `[질문 영문, 한글해석]` |
| 10 Describe the Picture | `describe` | 11TYPE ⚠ | `tests` = `[시험 구간 라벨 1, 2]`<br>`label` = 문장 구조 소제목<br>`sentences[]` = 예문 (최대 6, ①–⑥)<br>`picture` = `{ src, alt }` 이미지<br>`brainstorm[]` = `[그룹명, [질문, …]]` (가이드 켜면 노출) |
| 11 Respond to Questions | `respond` | 12TYPE | `test` = 시험 구간 라벨<br>`firstQuestion` = 첫 문항 번호(Q5)<br>`scenario` = `[박스 라벨, 문제 영문, 문제 해석]`<br>`items[]` = `[질문 영문, 질문 해석, 답변가이드 영문, 답변가이드 해석]` |
| 12 Phone Survey | `survey` | 13TYPE | 11과 같음 +<br>`picture` = `{ src, alt }` 이미지<br>`items[]` = `[질문 영문(숨김텍스트), 답변가이드 영문, 답변가이드 해석]` — 질문은 '보기'를 눌러야 보임 |

- 4TYPE: 현재 사용하는 교재 없음 → 템플릿 없음
- 같은 타입이 한 레슨에 여러 번 나와도 된다. 파트 화면은 `type`으로만 정해진다.

## 4. 화면에 있으나 ybmlms 항목 확인이 필요한 것

| 화면 요소 | BOOK_DATA | 확인 |
|---|---|---|
| 시험 구간 라벨 (`Part 3 (Q5~7) of the test`) | `test` · `tests` | ybmlms의 '파트 소제목'인지 별도 항목인지 |
| 문항 번호 시작값 (Q5, Q8) | `firstQuestion` | 데이터로 받는지, 파트 순서로 계산하는지 |
| 듣기 버튼 | (없음 — 항상 표시) | TTS 제공 여부 항목. 없는 문항은 버튼을 숨겨야 함 |
| 음성 | (없음) | 문항별 음성 URL 항목 |
| 답변TG (12 · 13TYPE) | (없음) | 강사용 문항별 TG. 현재 디자인은 파트 단위 `teacher`만 있음 → 노출 위치 결정 필요 |
| 해석 · 가이드 버튼 노출 | (없음 — 항상 표시) | PPT 7p: ybmlms 관리자 세팅이 있을 때만 노출. 세팅 항목명 확인 |

## 5. 데이터 규칙

- 문자열은 텍스트 그대로 넣는다(HTML 태그 없이). 화면에서 이스케이프한다.
- 빈칸 문장(3TYPE)은 빈칸 자리를 `( )`로 쓴다.
- 이미지는 파일 이름만 (`"img-2.jpg"`). 폴더는 `core.js`가 붙인다 (README 4장).
- 현재 코드는 `teacher`가 모든 파트에 있다고 가정한다. TG가 없는 파트가 있으면 개발에서 강사 가이드 박스를 숨김 처리한다.
